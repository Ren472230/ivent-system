# IVENT SYSTEM 0.1 Party Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a fully offline, single-file host application for running a party with players, stages, tokens, shop, inventory, effects, save slots, classic game stages, an in-app auction, event history, undo, and final statistics.

**Architecture:** The domain core is framework-independent TypeScript compiled into one browser script. State changes happen only through commands handled by a deterministic reducer. Browser storage, file import/export, timers, and DOM rendering are adapters around the core. The release build embeds JavaScript and CSS into one HTML file that opens through `file://`.

**Tech Stack:** TypeScript 5.x, browser DOM APIs, Node.js built-in test runner, TypeScript compiler, custom Node build script. No runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-15-ivent-system-design.md`

## Global Constraints

- Final artifact: one autonomous HTML file, usable offline via `file://`.
- Core must not depend on DOM, localStorage, network, or a concrete AI provider.
- All state changes go through commands and create log events.
- Domain randomness must use a saved seeded generator; direct `Math.random()` is forbidden in domain/game logic.
- Three save slots with primary copy, backup copy, metadata, export and import.
- Negative token balances are rejected unless a future configuration explicitly enables debt.
- Classic games are scenario modules; the auction is the first fully digital game.
- Primary desktop target: 1920x1080; required usable fallback: 1280x720.
- All core behavior follows test-first development.
